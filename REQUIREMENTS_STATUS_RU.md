# Контроль выполнения ТЗ — CRM автосервиса

Дата последней проверки: 01.08.2026

Последний блок: добавлен просмотр автомобиля с вкладкой страховых случаев и переходом в дело; в реестре страховых случаев добавлен поиск по нашим статусам; убраны лишние кнопки и поля каталожного номера/производителя; в истории записи на ремонт выводится исполнитель.

Статусы:

- **Готово** — сценарий реализован в backend и frontend.
- **Частично** — часть сценария работает, но есть незакрытые требования.
- **Не готово** — функционал ещё не реализован.

Денежные поля и AI не входят в текущий проход по отдельному указанию владельца проекта.

## 1. Базовая модель страхового случая

| Требование | Статус | Реализация / остаток |
|---|---|---|
| Страховой случай — отдельная сущность | Готово | `RepairCase`, таблица `work.w_repair_case` |
| Привязка случая к автомобилю | Готово | `car_id`, nested API `/cars/{carId}/repair-cases` |
| Несколько случаев у одного автомобиля | Готово | Нет ограничения «один автомобиль — один случай» |
| Создание с автоматическим статусом «Создан» | Готово | Backend принудительно ставит `CREATED` |
| Автомобиль и клиент подставляются из карточки авто | Готово | Автомобиль выбирается по VIN, данные владельца берутся из `Car` |
| Страховая компания | Готово | Справочник и выбор в форме |
| Номер страхового дела / направления | Готово | Поле `caseNumber` |
| Дополнительный номер дела | Готово | Убрано из новой формы создания |
| Ответственный исполнитель | Частично | При создании больше не запрашивается; назначается в диалоге записи на ремонт и отображается в карточке |
| Комментарий случая | Частично | Комментарий действия хранится при переходах; отдельное редактирование комментария карточки ещё не выведено |

## 2. Карточка обращения

| Требование | Статус | Реализация / остаток |
|---|---|---|
| Вкладка «Основное» | Готово | Данные авто, клиента, страховой и исполнителя |
| Вкладка «Работы» | Частично | Работы открываются внутри карточки и сохраняются в заказ-наряд; поля исполнителя и комментария ещё не добавлены |
| Вкладка «Запчасти» | Готово | Список, добавление, изменение, удаление, поставщик и даты |
| Вкладка «Документы» | Частично | В карточке есть видимая кнопка «Документы» и список сгенерированных документов; генерация зависит от сохранённого заказ-наряда |
| Вкладка «Фотографии» | Готово | Фото загружаются и удаляются внутри карточки случая |
| Вкладка «История» | Частично | История статусов и деталей выводится, имя пользователя добавлено; полный набор пользовательских действий ещё не записывается |
| Нет вложенных конфликтующих popup | Частично | Работы и фото открываются внутри карточки; формы действий вынесены в отдельные overlay, требуется финальная визуальная проверка старых сценариев |

## 3. Работы

| Требование | Статус | Реализация / остаток |
|---|---|---|
| Неограниченное количество работ | Готово | Строки `WorkOrderLine` |
| Название работы | Готово | В строке заказ-наряда |
| Исполнитель работы | Частично | Поле поддерживается backend-строкой, компактная форма работ пока показывает только название и единицу |
| Стоимость работы | Частично | Поле есть в заказ-наряде, но денежные разделы пока не развиваются |
| Комментарий работы | Частично | Поле поддерживается backend-строкой, компактная форма требует доведения |
| Работы привязаны к конкретному случаю | Готово | Заказ-наряд привязан через `repair_case_id` |

## 5. Статусная модель

| Статус | Статус реализации |
|---|---|
| Создан | Готово |
| Ожидание деталей | Готово |
| Детали поступили | Готово |
| Запись на ремонт | Готово | Кнопка открывает диалог исполнителя, даты, времени и комментария |
| Ремонт | Готово |
| Готов к выдаче | Готово |
| Автомобиль выдан | Готово | Кнопка открывает диалог получателя и комментария |
| Закрыт | Готово на уровне API, блокировка редактирования не завершена |

Ограничения переходов реализованы в `RepairCaseController`: действие проверяет текущий статус и не позволяет перескочить этап.

## 6. Кнопки действий

| Действие | Статус | Остаток |
|---|---|---|
| Заказать детали | Частично | Кнопка и API есть; полноценная карточка заказа деталей не выделена |
| Записать на ремонт | Готово | Кнопка/API и видимая форма исполнитель + дата + время + комментарий |
| Начать ремонт | Готово | Кнопка/API перехода есть, расширенные дата/время требуют завершения |
| Завершить ремонт | Частично | Проверка наличия заказ-наряда есть; проверка выполненных работ ещё упрощённая |
| Выдать автомобиль | Готово | Кнопка/API и видимая форма получателя + комментария |
| Закрыть случай | Частично | Кнопка/API есть; блокировка редактирования после закрытия ещё не завершена |
| Ручной выбор произвольного статуса | Частично | В новой карточке добавлены кнопки действий, но legacy-форма ещё содержит старый select статуса |

## 7. История

| Требование | Статус | Реализация / остаток |
|---|---|---|
| Создание случая | Готово | Автоматическая запись истории |
| Изменение статуса | Готово | Записываются предыдущий и новый статус |
| Добавление детали | Готово | Записывается имя детали |
| Изменение детали | Готово | Записывается действие изменения |
| Получение детали | Частично | Автопереход записывается; отдельная запись «получена деталь X» требует уточнения в UI |
| Запись на ремонт | Готово | Диалог передаёт поля в action API и пишет историю |
| Начало/завершение ремонта | Частично | Переход статуса записывается, дата/время и сотрудник ещё не полностью сохраняются |
| Выдача автомобиля | Готово | Диалог передаёт получателя и комментарий в action API и пишет историю |
| ФИО пользователя | Готово | API истории возвращает имя пользователя, а не только ID |
| Отсутствие технических записей | Частично | Основные записи человекочитаемые; legacy-события требуют чистки и унификации |

## 9. Защита от неправильных действий

| Правило | Статус |
|---|---|
| Нельзя заказать детали без деталей | Готово |
| Нельзя записать ремонт до получения деталей | Готово на API-уровне |
| Нельзя начать ремонт до записи | Готово на API-уровне |
| Нельзя выдать авто до завершения ремонта | Готово на API-уровне |
| Нельзя закрыть случай до выдачи | Готово на API-уровне |
| Нельзя редактировать закрытый случай | Готово на backend для случая, деталей и заказа-наряда |
| Нельзя завершить ремонт без выполненной работы | Готово |
