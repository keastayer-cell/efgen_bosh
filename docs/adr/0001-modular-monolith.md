# ADR-0001: модульный монолит

- Статус: принято
- Дата: 2026-07-31

## Контекст

Старая версия дублирует похожее API между Firestore adapter, Cloudflare Worker и
локальным `localStorage`. Бизнес-правила, безопасность, документы и AI-интеграция
смешаны с браузерным кодом.

## Решение

Новая версия строится как модульный монолит:

```text
Vue SPA -> Spring Boot REST API -> PostgreSQL
                         |
                         +-> закрытое файловое хранилище
                         +-> AI provider adapter
```

На уровне кода backend следует структуре `bg_foot_project`:

- `config`;
- `controller`;
- `domain`;
- `dto`;
- `health`;
- `repository`;
- `security`;
- `service`.

Границы предметных областей — автомобили, запчасти, контрагенты, заказ-наряды,
документы, дефектовка, аудит и резервные копии — отражаются именами классов и
сервисов внутри этих слоёв. Всё находится в одном deployable-приложении и одной
транзакционной базе.

## Почему не микросервисы

- предметная область пока небольшая;
- сущности тесно связаны;
- нужны простые транзакции;
- независимое масштабирование модулей не требуется;
- микросервисы увеличат эксплуатационную стоимость без бизнес-выгоды.

## Последствия

Положительные:

- одно место для бизнес-валидации;
- единая модель безопасности;
- нормальные транзакции;
- одна реализация API;
- проще тестировать и развертывать.

Ограничения:

- границы модулей придется соблюдать внутри одного приложения;
- AI и документы должны подключаться через собственные интерфейсы, чтобы внешние
  библиотеки не проникали в бизнес-модель.
